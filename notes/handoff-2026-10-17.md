## 当前使用方式

在 Control 目录：

```sh
bash scripts/dev.sh check
bash scripts/dev.sh pytest -q
bash scripts/verify-local-engine.sh
```

`dev.sh` 用隔离 uv 环境显式加载相邻 Engine，验证导入路径、版本、覆盖契约和 runtime；不依赖现有 `.venv`、不改锁文件、不读取预览私有配置。可设 `TESTPLAT_ENGINE_SOURCE` 指定其它源码目录。服务命令见 README；启动服务读取调用者环境 / `.env`，不会自动加载预览 `env.sh`。

Control 远程来源仍锁定 Engine 0.5.0 / `5231fb470dbb7a23b0d44489c49e2b8e88da7d36`。仅按该锁定安装不能提供当前覆盖能力，启动期会明确报缺少 `request_override`，引导使用本地入口。没有将远程不可获取的本地 SHA 填进 lock。

获授权后的顺序：先发布可获取的 Engine 提交，再更新 Control 精确 rev 与 lock，随后不带 editable / wheel 覆盖进行干净安装门禁。具体见 `testplat-control/docs/local-engine-delivery-2026-10-16.md`。

## 配置边界

决定：`docs/decisions/ADR-001-Web配置与本地Engine交付.md`。

默认 `TESTPLAT_LEGACY_GIT_CONFIG=false`。无数据库环境时返回空可选环境，API / Case 运行 422 引导配置；不会自动读取 Git 环境和历史 auth。数据库环境、host、账号缺失或停用均不回退服务器业务凭据。登录流程仍从 Git `_profiles.yaml` 读取。

仅历史兼容明确启用 `TESTPLAT_LEGACY_GIT_CONFIG=true`，且项目完全没有数据库环境行时才可使用 Git 环境 / auth。已有任何数据库环境行的项目即使开启兼容也不能回退，直接调用 `resolve_run_config` 同样受保护。保留原加载代码及旧记录解析测试。

pytest 默认关闭该开关，只对 `legacy_git_config` 标记启用。历史 Phase 4.0 矩阵显式开启；现代 Web 门禁先创建数据库环境。不要把整个套件切到兼容模式来“修复”测试。
